# Технічне завдання — CAD Controller for AutoCAD2026

(Стислий витяг; повна специфікація у цьому документі)

Мета
- Автоматизовано відновлювати 3D-модель із двох ортогональних проекцій (DWG/DXF або растрові скани), створювати третю проекцію, розпізнавати розрізи, перерізи, різьбу, матеріали, нормативи (GOST/ISO/DIN), формувати комплект конструкторської документації (КД).

Архітектура
- AutoCAD плагін (C#, .NET Framework 4.8) — UI, експорт 2D, імпорт 3D.
- Локальний Python ML сервер (FastAPI) — preprocessing, rule-based reconstruction, ML inference, постобробка.

Ключові компоненти
- Експорт 2D (линії, дуги, полілінії, тексти)
- Семантичне розпізнавання (OCR + ML)
- Правила реконструкції (циліндр, отвір, призма)
- Генерація КД (DWG/PDF/BOM)
- База метаданих (SQLite)

Pipeline
1. Експорт 2D → JSON
2. Запит на server:/reconstruct
3. Обробка: вирівнювання, відповідність контурів, rule-based & ML
4. Повернення 3D parts → імпорт в DWG
5. Перевірка користувачем, правки, генерація КД

Ключові інтерфейси
- Формат обміну: JSON (metadata + entities + annotations)
- REST API endpoint:
  - POST /reconstruct — приймає експортний JSON, повертає parts JSON
- Плагін взаємодіє з локальним сервером через HTTP (127.0.0.1)

ML та дані
- Анотації: COCO-like + додаткові CAD-метадані
- Моделі:
  - Сегментація (U-Net / DeepLab) для розпізнавання контурів/швів
  - Keypoint / Graph matching для відповідності елементів між проекціями
  - Parametric predictor — для відновлення параметричних елементів (циліндри, отвори)
- Тренування:
  - Створювати synthetic dataset із CAD моделей для розширення датасету
  - Валідація на наборах стандартних деталей (гайки, болти, корпуси)

Тестування
- Unit: експорт/імпорт, round-trip (2D→server→3D→експорт)
- Integration: AutoCAD plugin + локальний server на тестовій VM
- Acceptance: набір стандартних деталей, точність відновлення геометрії (погрішність розмірів)

Безпека та розгортання
- Локальний сервер — запуск лише на localhost; доступ обмежений
- Для корпоративного розгортання — контейнеризація (Docker) + VPN/колбеки для ML-релізів
- Інструменти CI/CD: GitHub Actions для збірки сервера; self-hosted Windows runner для збірки плагіна (через ліцензійні AutoCAD SDK)

Ризики
- Неповні/пошкоджені креслення → погана якість реконструкції
- Ліцензійні обмеження AutoCAD SDK (не можна публічно розповсюджувати деякі бінарні файли)
- Складні органічні форми не піддаються rule-based підходу — потрібні ML моделі високої складності

Дорожня карта (орієнтовно)
- M0: Інтеграція експорту/імпорту, базовий rule-based сервер
- M1: Додавання простих ML правил (arc→cylinder, hole detection)
- M2: Підсилення dataset + тренування сегментатора
- M3: Рефакторинг інтерфейсів, інтеграція з CI/CD, інсталятор/підпис
- M4: Підтримка складніших частин, генерація КД (PDF/BOM)
- M5: Оптимізація UX та випуск першої продуктивної версії

Додаткові нотатки
- Формати обміну й API повинні залишатися простими та розширюваними (версіювати).
- Документація для розробників: приклади JSON, набір тестових CAD-файлів.
- Логування та трасування обробки (збереження проміжних результатів для діагностики).
